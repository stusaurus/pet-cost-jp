# ビジュアル操作体験の再設計

## 監査

2026-09-30、公開サイトをPCと390×844のiPhone相当幅で操作。トップ、全3カテゴリ、条件変更、固定サマリー、最安、TOP3、比較視点、一覧、店頭計算、楽天導線を確認。

| 問題 | 対応 |
| --- | --- |
| スマホの最初の画面が大きな紹介と画像で埋まり、条件選択に届かない | 紹介を短くし、全条件を折り返して表示 |
| 最安の表紙・王冠・商品画像が単価の結論より強い | 条件、単価、中央値との差、計算根拠を先に表示 |
| TOP3が広告のような独立カードで価格差を比べられない | 0円からの共通尺度のバーと、1位からの差を表示 |
| 3つの角度が独立した楽天リンクで、選び方として触れない | 単価・初期支出・まとめ買いを切り替える操作に統合 |
| 全商品が大きく、上位の表紙と情報が重複 | 一覧を価格中心の行へ。上位3件だけ軽い強調、4位以下は密度を上げる |
| スマホの固定サマリーでは中央値との差を見失う | 4つの情報を保ったままスクロールで約60pxへ縮小 |
| 算出済みの商品にも「価格特徴を比較中」が残る | 現在条件の安さ理由・中央値との関係を即時に算出 |
| 店頭計算は単位が曖昧で、条件変更後の基準価格が古い | 枚・Lを明示、入力エラーと比較バーを追加。基準を自動更新 |
| スクロール時の装飾フェードが内容を一時的に隠す | 常時演出を撤去。操作時の180msの応答に限定 |
| トップの編集記事と日次の価格差カードが同じ情報を反復 | 価格差の図とカテゴリ入口を3つのタイルへ統合 |

## 比較の正確さ

- 商品取得・数量解析・分類・品質判定・重複排除・単価計算は既存の処理を維持。
- 中央値は偶数件の場合、中央2件の平均へ修正。初期HTMLと操作後JSの計算をそろえた。
- 「送料別」の送料は未加算と明示。商品総額と実際の最終支払額を混同させない。
- 猫砂の「すべて」は異素材・用途が混在することを明示し、素材選択へ誘導。
- 表示用の商品名だけ販促の括弧を整理。元の商品名・URL・商品IDはデータと計測に維持。
- 過去最安・値下げ・セールを示すグラフではない。現在掲載中の商品の分布のみを表示。

## 整理・計測

旧版の重複CSS・王冠・表紙・装飾イラスト・スクロール出現処理を撤去。共通CSSを単一ファイルへ整理し、同じ結果状態から全比較パーツを更新する。

既存イベント9種を保持：comparison_view、comparison_filter、unit_calculator_use、affiliate_click、product_result_click、view_item_list、select_item、homepage_editorial_click、daily_spotlight_click。

comparison_angle_selectを追加。comparison_filterに件数・最安・中央値を追加。自動再計算では店頭利用イベントを重複送信しない。運営者検証のoperator_testと全イベントのsite_idも保持。

## 検証

- Python29件：既存の商品品質・数量回帰に加え、初期条件、静的ランキング、中央値、空結果、SEO、URL・計測属性、表示名の安全性、Search Consoleファイルコピー。
- JS9件：全3カテゴリの全表示フィルター、順位1〜3、理由4種、TOP3の尺度、比較視点、店頭計算・入力エラー・基準更新、同単価・1件・0件、GA4の既存イベントと追加イベント、reduced motion。
- 本番Actionsでも、APIで取得した商品と生成画面に同じJS回帰検証を適用。PRではSecretsを使わず既存監査済みデータで検証する。
